# TF2 Trade Suite Tools — Руководство разработчика и архитектура

> **Внутренняя техническая документация проекта** (архитектура, реализация модулей, протоколы взаимодействия и оптимизации).
> Пользовательская документация и инструкция по установке находятся в главном [README.md](README.md).

Кроссбраузерное расширение для трейдинга в Team Fortress 2, построенное на стеке **WXT + TypeScript + Vue 3**.
Архитектура проекта спроектирована с соблюдением шести ключевых требований:

1. **Модульность и гранулярная настройка** — каждый модуль включается и выключается независимо, функции сгруппированы по целевым сайтам.
2. **Кроссбраузерность** — единая кодовая база собирается в Chrome/Edge/Brave/Opera (Manifest V3) и Firefox (Manifest V2).
3. **Единый реестр и прозрачность источников** — каталог функций (`utils/registry.ts`) исключает дублирование логики и фиксирует источники (`portedFrom`).
4. **Сводка валюты инвентаря** — быстрый подсчёт ключей и металла по всему инвентарю обеих сторон трейда прямо в окне обмена.
5. **Изолированный единый визуал** — инжектируемый UI работает через Shadow DOM (`createShadowRootUi`) и общую дизайн-систему токенов (`styles/tokens.css`).
6. **Атрибуты и иконки предметов** — отображение Unusual-эффектов, Strange-счётчиков, Spells (с подробными векторными SVG-иконками), Killstreak-тиров и крафтовости во всех основных сценариях трейда.

## 1. Общая архитектура

### Структура проекта

```
entrypoints/               Точки входа расширения (content scripts, popup, options)
  *.content.ts             ISOLATED-скрипты: монтируют UI, управляют жизненным циклом
  *-core.content.ts        MAIN-скрипты: взаимодействуют с глобальными объектами страницы Steam
  options/                 Страница настроек на Vue 3
  popup/                   Компактное меню расширения
modules/<feature-id>/      Модульная логика функций
  core.ts                  Логика уровня страницы (MAIN world)
  panel.ts / panel.css     UI компоненты (ISOLATED world)
  types.ts                 Интерфейсы сообщений и RPC-контракты
utils/                     Переиспользуемое ядро
  registry.ts              Единый реестр функций (источник правды)
  settings.ts              Реактивная обёртка над browser.storage
  bridge.ts                Шина RPC через window.postMessage
  currency.ts              Арифметика валюты TF2 (Defindex, усечение metal, парсинг)
  trade-offer.ts           Утилиты работы с офферами Steam (getInventory, addItems)
  item-attributes.ts       Парсинг атрибутов предметов (Unusual, KS, Spells)
  item-attribute-render.ts Рендерер бейджей и SVG-иконок
  inventory-watch.ts       Сетевой перехватчик инвентаря
styles/
  tokens.css               Переменные цветов качества TF2, теней и типографики
  item-attributes.css      Стили бейджей и рамок предметов
```

### Модель изоляции: MAIN vs ISOLATED World

Веб-страницы Steam размещают критически важные структуры данных (`UserYou`, `UserThem`, `g_rgCurrentTradeStatus`, `g_rgAppContextData`, `CInventory`) непосредственно в глобальном контексте страницы. Стандартный изолированный контекст расширений (`ISOLATED`) не имеет к ним прямого доступа.

Архитектура разделяет ответственность каждого сложного модуля на две половины:
- **MAIN-world скрипты (`*-core.content.ts`)**: выполняются в контексте страницы с `runAt: 'document_start'`. Они считывают данные памяти Steam, подписываются на события и управляют добавлением предметов. У них нет доступа к `browser.storage`.
- **ISOLATED-world скрипты (`*.content.ts`)**: имеют доступ к API браузера (`browser.storage.sync`), слушают настройки и монтируют пользовательский интерфейс в защищённый Shadow DOM.

### Шина межконтекстного взаимодействия (Bridge RPC)

Связь между `MAIN` и `ISOLATED` реализована в `utils/bridge.ts` через `window.postMessage` с пространством имён `__tf2suite__`:
- Каждому запросу присваивается уникальный UUID.
- Поддерживается строгая типизация запроса и ответа на основе TypeScript Generics.
- Встроен защитный таймаут от зависания промисов.
- Ответственность за включение/отключение модуля несёт исключительно ISOLATED-мир: если тумблер выключен, ISOLATED не отправляет запросы и очищает смонтированный UI.

### Дизайн-система и Shadow DOM

Все всплывающие и плавающие панели расширения монтируются через WXT-хелпер `createShadowRootUi`.
- Внутри Shadow DOM разметка оборачивается в `<div class="tf2s-root">`.
- Стили хост-страниц не ломают компоненты расширения, а внутренние стили расширения не влияют на стили Steam.
- В `styles/tokens.css` определены унифицированные цвета рамок качества TF2 (Unusual `#8650AC`, Strange `#CF6A32`, Vintage `#476291`, Genuine `#4D7455` и т.д.), отступы, тени и базовые классы компонентов (`.tf2s-panel`, `.tf2s-btn`, `.tf2s-badge`).

### Система локализации (i18n)

Расширение полностью двуязычно (**Русский** и **Английский**):
- Язык по умолчанию — `ru`, переключение в настройках применяется на лету.
- Каждый модуль держит локальный словарь интерфейса рядом со своим кодом (`const UI = { ru: {...}, en: {...} } as const`).
- Игровая терминология TF2 (названия спеллов, эффектов, Killstreaker, Sheen, Strange Parts) сохраняется в оригинале на английском языке во всех локалях для исключения разночтений с торговыми площадками.
- При смене языка контент-скрипты автоматически переинициализируются (`ui.remove()` → `ui.mount()`).

## 2. Каталог и техническое описание модулей

В расширении функционируют **24 независимых модуля**, охватывающих 8 веб-ресурсов.

### Окно трейд-оффера Steam (`/tradeoffer/*`)

#### 1. `wallet-summary` — Сводка валюты в инвентаре
- **Назначение**: отображает суммарный баланс валюты (ключи, рефы, реки, скрап и общий итог в ref) во всём инвентаре пользователя и партнёра.
- **Архитектура**: плавающее перемещаемое окно с двумя колонками. Читает инвентарь напрямую из оперативной памяти страницы (`getInventory`) за < 1 мс. В случае холодного старта использует резервный сетевой запрос `fetchCurrencyWallet` с TTL-кэшем 60 секунд.

#### 2. `quick-add-items` — Быстрое добавление предметов и валюты
- **Назначение**: панель быстрого переноса предметов в оффер (Items, Keys, Metal, Recent), очистка слотов оффера (`Clear Me` / `Clear Them`), смещение выборки по индексу.
- **Режимы металла**:
  - `combined` — жадный размен суммы в ref на Refined → Reclaimed → Scrap;
  - `split` — раздельные кнопки «Реф», «Рек», «Скр» для точного поштучного набора.
- **Интеграция с занятыми предметами**: кнопки `[ Ключи (своб.) ]` и `[ Металл (своб.) ]` выбирают валюту исключительно из свободных `assetId`.
- **Клонирование офферов**: выпадающий список `[ 📋 Из оффера ▾ ]` дублирует набор предметов из любого активного отправленного оффера прямо в текущий трейд.
- **Работа со слотами Steam**: манипулирует массивами `win.g_rgCurrentTradeStatus.me.assets` на месте (`length = 0` при очистке, `slots.push` при добавлении) с покадровой синхронизацией `RefreshTradeStatus` через `requestAnimationFrame`.

#### 3. `auto-fill-from-listing` — Автозаполнение из объявлений backpack.tf
- **Назначение**: автоматическое добавление предмета партнёра по параметру ссылки `for_item` и встречной валюты по параметрам `listing_currencies_*` без кликов со стороны пользователя.
- **Механизм**: опрашивает готовность инвентаря партнёра; для объявлений на покупку выполняет сопоставление своего предмета по `listing_item_name`.

#### 4. `listing-price-button` — Кнопка добавления цены объявления
- **Назначение**: автономная ручная кнопка «Добавить цену объявления» в окне трейда.
- **Защита**: подсчитывает валюту, уже лежащую в слотах оффера (`getCurrentCurrency`), и добавляет только недостающую разницу, исключая задвоение при параллельной работе с автозаполнением.

#### 5. `trade-item-summary` — Сводка предметов и валюты в трейде
- **Назначение**: встроенные полоски чипов под заголовками сторон трейда. Считает реальное содержимое слотов оффера.
- **Режимы**:
  - `simple` — отображает количество ключей, металла и число прочих предметов;
  - `priced` — рассчитывает суммарную стоимость не-валютных предметов через API PriceDB.io с построчной детализацией и ссылками на проверку цен.

#### 6. `trade-item-attributes` — Иконки и атрибуты в окне трейда
- **Назначение**: оверлей атрибутов на плитках предметов (Unusual-эффекты с анимированным фоном, Strange, Uncraftable, Spells, Killstreak, Lowcraft).
- **Режимы детализации**: «Просто» (лаконичные текстовые бейджи) или «Подробно» (индивидуальные векторные SVG-иконки для каждого спелла и килстрик-тира).

#### 7. `trade-committed-items` — Занятые предметы в активных офферах
- **Назначение**: предотвращает отмену офферов по ошибке «Items Now Unavailable For Trade» при параллельной отправке предложений с одними и теми же предметами.
- **Визуальные стили**: значок `⇄`, настраиваемая цветная рамка и фоновая подложка с регулировкой прозрачности.
- **Классификация активных офферов**: фильтрует архивные офферы по наличию нативной кнопки отмены `CancelTradeOffer` и отсутствию статусных баннеров `.tradeoffer_items_banner`.
- **Изоляция валюты**: для ключей и металла сопоставление выполняется строго по конкретному `assetId`, исключая ложное срабатывание по общему `classid`.

### Списки офферов и история (`/tradeoffers*`, `/tradehistory*`)

#### 8. `instant-accept-decline` — Быстрое принятие и отклонение офферов
- **Назначение**: кнопки прямого действия на активных входящих офферах без необходимости открывать отдельную страницу обмена.
- **Сетевой протокол**: отправляет `POST /tradeoffer/<id>/accept` и `/decline` с передачей `sessionid` и обязательного заголовка `Referer: https://steamcommunity.com/tradeoffer/<id>/`.

#### 9. `decline-all-active` — Массовое отклонение активных офферов
- **Назначение**: кнопка пакетного отклонения всех активных входящих офферов с подтверждением перед запуском. Запросы выполняются последовательно с паузой 350 мс для защиты от троттлинга Steam.

#### 10. `offer-item-summary` — Схлопывание дубликатов с бейджем количества
- **Назначение**: объединяет повторяющиеся одинаковые предметы в сетке оффера в один тайл с индикатором `×N`, снижая визуальный шум при крупных трейдах.

#### 11. `offer-currency-total` — Итог валюты по офферам
- **Назначение**: двухколоночная плашка над каждым оффером и строкой истории, показывающая итоговую сумму ключей и металла, отдаваемых и получаемых каждой стороной. Учитывает множители `×N` от `offer-item-summary`.

#### 12. `offers-item-attributes` — Атрибуты предметов в списках офферов и истории
- **Назначение**: подгрузка атрибутов предметов (Unusual, Spells, Killstreak) на странице списка офферов через эндпоинт `/economy/itemclasshover/`.
- **Особенности**: кэширование промисов для исключения дублирующих запросов по одинаковым предметам, очередь запросов (до 5 параллельно) и точный синтаксический парсер HTML-ответа с вызовом `BuildHover`.

### Инвентарь Steam (`/inventory/*`)

#### 13. `inventory-currency-counter` — Счётчик валюты в дизайне Steam
- **Назначение**: панель подсчёта ключей и металла, встроенная под нативными фильтрами инвентаря (`.filter_ctn`). Мгновенный сбор данных из памяти страницы без лишних сетевых вызовов, кнопка ручного полного пересчёта.

#### 14. `pricedb-check-button` — Кнопка проверки цены на PriceDB.io
- **Назначение**: кнопка в карточке выбранного предмета инвентаря (`#iteminfoN`), ведущая на страницу предмета на PriceDB.io. Устойчива к перерисовкам React-контейнера при смене выбранного слота.

#### 15. `inventory-item-attributes` — Атрибуты предметов в инвентаре
- **Назначение**: рендеринг Unusual-анимаций, рамок и бейджей спеллов в сетке инвентаря.
- **Поддержка виртуализации**: отслеживает смену `id` тайлов при постраничной навигации Steam инвентаря (`attributeFilter: ['id']`), обновляя оверлеи без утечек памяти.

## 3. Оптимизация производительности (v1.2.1)

В версии v1.2.1 проведена масштабная оптимизация производительности для устранения задержек при загрузке страниц Steam и открытии торговых предложений:

1. **In-Memory Fast Path (`getInventory`)**:
   - Реализовано прямое извлечение данных инвентаря из оперативной памяти страницы (`g_rgAppContextData`, `UserYou.getInventory`, `UserThem.getInventory`, `rgContexts`).
   - Подсчёт валюты в `wallet-summary` и `trade-item-summary` выполняется за < 1 мс без единого сетевого запроса, предотвращая ошибки `429 Too Many Requests`.
   - Резервный сетевой фетч снабжён 60-секундным кэшем.
2. **Ранняя инициализация core-скриптов (`runAt: 'document_start'`)**:
   - Все фоновые скрипты окна трейда регистрируют RPC-приёмники до парсинга DOM, устраняя таймауты моста при раннем монтировании UI.
3. **Устранение блокировки главного потока**:
   - Полностью исключена сериализация `document.documentElement.innerHTML`.
   - Определение идентификаторов переведено на чтение cookies, глобальных переменных и быстрый перебор инлайн-скриптов (сокращение времени с 200–500 мс до 0.2 мс).
4. **Безотказный рендеринг атрибутов**:
   - Добавлен сквозной fallback по `assetId` при переключении между инвентарями.
   - Слушатели событий клика по вкладкам инвентаря запускают немедленное обновление без ожидания интервалов таймера.
5. **Снижение фоновой нагрузки CPU**:
   - Пропуск сканирования DOM-дерева в `inventory-apply` и `tradeoffer-apply`, если в хранилище нет активных занятых офферов (`committedMap.size === 0`).
   - Увеличение интервалов резервных таймеров с 1200 мс до 3000 мс с опорой на события мутаций и кликов.
6. **Оптимизация модуля занятых предметов (`trade-committed-items`)**:
   - **Устранение принудительного синхронного лейаута (Reflow)**: полностью исключены циклические вызовы `window.getComputedStyle()` внутри циклов обхода элементов инвентаря и оффера.
   - **CSS-переменные вместо инлайн-стилей**: цвета рамок и заливки вынесены в CSS-переменные `--tf2s-committed-*` и CSS-классы `.tf2s-committed--border` / `.tf2s-committed--bg`, что позволяет браузеру производить стилизацию за один проход без манипуляций со `style`.
   - **Разрыв бесконечной петли MutationObserver**: из `attributeFilter` наблюдателей исключен атрибут `style`, и добавлена фильтрация собственных DOM-изменений расширения (бейджей, классов), что устранило каскадный ретриггер сканирования каждые 80 мс.
   - **Таргетированные обработчики кликов**: глобальный захват кликов на `document` заменен на целевое делегирование по кликам на вкладки и пагинацию инвентаря (`.pagebtn`, `.inventory_tab`, `[id^="inventory_select_"]`).
   - **Кулдаун сетевой синхронизации**: добавлена блокировка повторных сетевых запросов (`SYNC_COOLDOWN_MS = 60_000`) и дедупликация параллельных сетевых синхронизаций при переключении и альт-табе между вкладками.

## 4. Сборка и руководство по разработке

### Команды сборки

```bash
# Установка зависимостей
npm install

# Режим разработки с Hot Reload
npm run dev            # Chrome (MV3)
npm run dev:firefox    # Firefox (MV2)

# Проверка типов TypeScript
npm run compile        # vue-tsc --noEmit

# Финальная сборка
npm run build          # Сборка Chrome MV3 в .output/chrome-mv3
npm run build:firefox  # Сборка Firefox MV2 в .output/firefox-mv2

# Создание zip-архивов для публикации
npm run zip
npm run zip:firefox
```

### Загрузка в браузер

- **Chrome / Edge / Brave / Opera**:
  1. Перейдите на страницу `chrome://extensions`.
  2. Включите **«Режим разработчика»** (Developer mode).
  3. Нажмите **«Загрузить распакованное расширение»** (Load unpacked) и укажите папку `.output/chrome-mv3`.
- **Firefox**:
  1. Перейдите на страницу `about:debugging#/runtime/this-firefox`.
  2. Нажмите **«Загрузить временное дополнение»** (Load Temporary Add-on).
  3. Выберите файл `manifest.json` внутри `.output/firefox-mv2`.

### Создание нового модуля

1. **Регистрация в реестре (`utils/registry.ts`)**:
   - Добавьте объект конфигурации в `FEATURE_REGISTRY`: `id`, `site`, двуязычные `title`/`description`, `defaultEnabled` и `status: 'planned'`.
2. **Создание структуры модуля (`modules/<id>/`)**:
   - `types.ts` — типизация запросов и ответов шины;
   - `core.ts` — логика для MAIN-мира страницы (при необходимости доступа к JS-объектам);
   - `panel.ts` + `panel.css` — изолированный UI с использованием токенов `styles/tokens.css` и локальным словарем интерфейса `const UI = { ru: {...}, en: {...} }`.
3. **Точки входа (`entrypoints/`)**:
   - Создайте `<id>.content.ts` (ISOLATED) с проверкой `isFeatureEnabled(id)` и подпиской `watchSettings`.
   - При необходимости доступа к странице создайте `<id>-core.content.ts` (MAIN) с `runAt: 'document_start'`.
4. **Завершение**:
   - Переведите `status` модуля в реестре на `'ready'`. Тумблер в настройках и всплывающем окне появится автоматически.
